MELO — страница услуги для темы oxboxwise
==========================================

Это НЕ отдельная тема. Это три файла, которые кладутся в действующую
тему oxboxwise. Шапка, меню, подвал, попапы и формы остаются вашими —
шаблон вызывает get_header() и get_footer().

Предыдущий архив был собран как самостоятельная тема — это была ошибка
постановки задачи, приносим извинения за потраченное время.


ЧТО КУДА КЛАСТЬ

Скопировать содержимое папки oxboxwise/ в wp-content/themes/oxboxwise/,
сохранив структуру. Ничего не перезаписывается — все файлы новые:

  templates/template-melo-service.php   шаблон страницы
  css/melo-page.css                     стили (40 КБ)
  js/melo-page.js                       скрипт (3 КБ)
  img/melo/                             8 картинок, 1.4 МБ


ПОДКЛЮЧЕНИЕ

Стили и скрипты у вас подключаются тегами прямо в header.php
(wp_enqueue_* там закомментированы). Добавьте две строки туда же,
рядом с остальными — перед <?php wp_head(); ?>:

  <?php if ( is_page_template( 'templates/template-melo-service.php' ) ) : ?>
    <link rel="stylesheet" href="<?=get_template_directory_uri()?>/css/melo-page.css?v=<? echo time() ?>">
    <script defer src="<?=get_template_directory_uri()?>/js/melo-page.js?v=<? echo time() ?>"></script>
  <?php endif; ?>

Условие нужно, чтобы файлы грузились только на этой странице и не
весили на остальных.


КАК СОЗДАТЬ СТРАНИЦУ

1. Страницы → Добавить новую.
2. Заголовок страницы станет H1 первого экрана.
3. Атрибуты страницы → Шаблон → «MELO — страница услуги».
4. Изображение записи станет фоном первого экрана (нужен горизонтальный
   кадр ~1920×1069). Не задано — возьмётся img/melo/hero.jpg.
5. Отрывок (excerpt) станет подзаголовком под H1. Не задан — подставится
   текст по умолчанию из шаблона.


ПОЧЕМУ ЭТО НЕ СЛОМАЕТ САЙТ

Весь контент шаблона обёрнут в <div class="melo-page">, и КАЖДОЕ правило
в melo-page.css заскоуплено под этот класс. Проверено обходом CSSOM:
238 правил, ни одного селектора без .melo-page.

Это важно, потому что в исходной вёрстке есть сброс на html/body/img/a/
ul/h1-h4 и классы, которые у вас уже заняты: container, btn, nav,
nav__link, breadcrumbs, service, service__item, service__title,
project__title. Без изоляции они бы переписали ваши.

Имена ключевых кадров тоже с префиксом: melo-veil-in, melo-hero-rise,
melo-hero-fade.

Скрипт ищет элементы только внутри .melo-page и на других страницах
не делает ничего. jQuery не требуется.

Проверено на копии живой melodesign.ru: шапка, подвал, ваши секции,
модалки и кнопки .open-modal-os остались нетронутыми, переполнения по
горизонтали нет.


ЧТО СВЯЗАНО С ВАШИМ КОДОМ

- Кнопка «Обсудить проект» несёт ваши класс open-modal-os и data-title,
  поэтому открывает ваш попап и подставляет тему заявки.
- Хлебные крошки выводит сама тема (get_template_part в header.php).
  В шаблоне свой блок крошек закомментирован — если захотите их внутри
  первого экрана, раскомментируйте и отключите вывод темы.
- GSAP ScrollSmoother у вас подключён, но обёртки #smooth-wrapper на
  страницах нет, поэтому наши прокруточные эффекты работают штатно.
  Если будете включать ScrollSmoother — скажите, переведём появление
  блоков на ScrollTrigger.


ГДЕ ПРАВИТЬ СОДЕРЖИМОЕ

Всё в начале templates/template-melo-service.php:

  $service_title, $service_image  заголовок и картинка второго блока
  $service_items                  пять позиций «Что входит в услугу»
  $steps                          четыре этапа «Как мы работаем»
  $projects                       шесть примеров реализации

У вас стоит ACF Pro и есть тип записи projects — массивы сделаны так,
чтобы их можно было заменить на WP_Query или поля ACF, не трогая
разметку внутри foreach.

Иконки лежат SVG-спрайтом в самом шаблоне, рисуются currentColor.
Своя иконка: добавить <symbol id="melo-i-имя"> в спрайт и указать это
имя в поле icon массива $service_items.


ЧЕГО НЕ ЛОМАТЬ

1. Инлайновый скрипт перед <div class="melo-page">. Он ставит класс .js
   и через 2.5 секунды включает аварийный показ, если melo-page.js не
   загрузился. Уберёте — при сбое скрипта страница окажется пустой:
   блоки до появления стоят в opacity: 0.

2. Появление блоков считается через getBoundingClientRect по событиям
   scroll/resize/load, а НЕ через IntersectionObserver. Наблюдатель
   отдаёт результат асинхронно и только при отрисовке кадра, а прокрутку
   браузер восстанавливает после выполнения скриптов — из-за этого при
   F5 на середине страницы видимая часть оставалась пустой.

3. У .card__media, .project__media и .service__media подъём, тень и
   шторка перечислены ОДНИМ объявлением transition. Разносить нельзя:
   сокращённая запись заменяет весь список целиком.


ЧТО ОСТАЛОСЬ НА ВАШЕЙ СТОРОНЕ

  • Фотографии — плейсхолдеры, вырезаны из макета. Пропорции и пути
    проставлены, менять только файлы в img/melo/.
  • Ссылки проектов ведут на "#" — подставьте реальные или замените
    массив на WP_Query по типу записи projects.
  • Кнопка «Все проекты» ведёт на /projects/ — поправьте, если адрес
    другой.
  • Ширина контента внутри блока — 1840px при 1920 (токен --container
    в начале css/melo-page.css). У сайта 95.05vw. Если нужно вровень
    с остальными страницами, поменяйте одно значение.
  • Шрифты Golos Text и Merriweather тянутся с Google Fonts и в этом
    файле НЕ подключены. Добавьте в header.php:
    <link href="https://fonts.googleapis.com/css2?family=Golos+Text:wght@400;500;600;700&family=Merriweather:wght@400;700&display=swap" rel="stylesheet">
    Для российского хостинга лучше положить локально.
