MELO — внутренние страницы для темы oxboxwise
==============================================

Это НЕ отдельная тема. Это файлы, которые кладутся в действующую тему
oxboxwise. Ставится за десять минут, ничего не перенатягивая.

Страницы идут в НОВОЙ стилистике MELO целиком — включая шапку и подвал.
Старая шапка темы на них не выводится: у страниц свой каркас документа.
Это сознательно, сайт переделывается.


ЧТО КУДА КЛАСТЬ

Скопировать содержимое папки oxboxwise/ в wp-content/themes/oxboxwise/,
сохранив структуру. Ничего не перезаписывается — все файлы новые:

  templates/template-melo-direction.php   шаблон со слайдером направлений
  templates/template-melo-service.php     шаблон со списком «что входит»
  template-parts/melo-header.php          каркас: head, наша шапка, меню
  template-parts/melo-footer.php          наш подвал, контакты, wp_footer
  inc/melo-functions.php                  две функции: контакты и меню
  css/melo-page.css                       стили, общие для обоих (41 КБ)
  js/melo-page.js                         скрипт, общий для обоих (6 КБ)
  img/melo/                               11 картинок, 1.6 МБ


ПОДКЛЮЧЕНИЕ — ОДНА СТРОКА

В functions.php темы, рядом с остальными require:

  require get_template_directory() . '/inc/melo-functions.php';

Больше ничего добавлять не нужно. CSS и JS подключает сам каркас
melo-header.php, и только на своих страницах — на остальных они не
грузятся вообще.


КАК СОЗДАТЬ СТРАНИЦУ

1. Страницы → Добавить новую.
2. Заголовок страницы станет H1 первого экрана.
3. Атрибуты страницы → Шаблон:

   «MELO — направление деятельности»  второй блок — слайдер из пяти
                                      карточек с фотографиями
   «MELO — страница услуги»           второй блок — список из пяти
                                      позиций с иконками и картинка

   Оба шаблона универсальные: заголовок, подзаголовок и фон берутся из
   самой записи, страниц на каждом можно завести сколько угодно.

4. Изображение записи станет фоном первого экрана (нужен горизонтальный
   кадр ~1920x1069). Не задано - возьмётся img/melo/hero.jpg.
5. Отрывок (excerpt) станет подзаголовком под H1. Не задан - подставится
   текст по умолчанию из шаблона.


МЕНЮ И КОНТАКТЫ

Меню берутся из админки, из ваших же областей: «Главное» в шапке,
«В подвале» - в подвале. Пока область не назначена, показывается
запасной набор из шаблона, страница не ломается.

Разметка меню плоская, без ul/li - так в макете. Поэтому вместо
wp_nav_menu используется своя функция melo_nav(), она читает то же
самое меню из админки.

Контакты (телефон, почта, адрес, оффер) лежат в inc/melo-functions.php
как значения по умолчанию и переопределяются фильтром, без правки
шаблонов:

  add_filter( 'melo_contacts', function ( $data ) {
      $data['phone']      = '+7 843 000 00 00';
      $data['phone_raw']  = '+78430000000';
      $data['phone2']     = '8 800 000 00 00';
      $data['phone2_raw'] = '88000000000';
      $data['email']      = 'hello@melodesign.ru';
      $data['address']    = 'г. Казань, ул. Ленина 00';
      $data['telegram']   = 'https://t.me/...';
      $data['policy']     = '/policy/';
      return $data;
  } );


ПОЧЕМУ ЭТО НЕ СЛОМАЕТ САЙТ

Две защиты, и нужны обе.

1. Всё заскоуплено под .melo-page - контейнер, в который обёрнут весь
   контент страницы. Проверено обходом CSSOM: 238 правил, ни одного
   селектора без .melo-page. Это защищает САЙТ ОТ НАС: в исходной
   вёрстке есть сброс на html/body/img/a/ul/h1-h4.

2. Все наши классы получили префикс melo-: melo-container, melo-btn,
   melo-service и так далее, всего 112 классов. Это защищает НАС ОТ
   САЙТА - и без второго шага первый бесполезен.

   У вас заняты container, btn, nav, nav__link, breadcrumbs, service,
   service__item, service__title, project__title. Ваши правила
   протекали внутрь наших блоков по свойствам, которые мы не задаём:
   на первом прогоне секция «Что входит в услугу» получила синий фон
   от вашего .service.

Имена ключевых кадров тоже с префиксом: melo-veil-in, melo-hero-rise,
melo-hero-fade. Скрипт ищет элементы только внутри .melo-page. jQuery
не требуется.


ЧТО СВЯЗАНО С ВАШИМ КОДОМ

- GSAP ScrollSmoother у вас подключён, но обёртки #smooth-wrapper на
  страницах нет, поэтому наши прокруточные эффекты работают штатно.
  Будете включать - скажите, переведём появление блоков на ScrollTrigger.
- Кнопка «Обсудить проект» ведёт на якорь #contacts - на контакты в
  подвале. Если нужен ваш попап вместо этого, добавьте кнопке класс
  open-modal-os и data-title, а модалки выведите в melo-footer.php.


ГДЕ ПРАВИТЬ СОДЕРЖИМОЕ

Всё в начале файлов шаблонов:

  templates/template-melo-direction.php
      $cards_title, $cards   заголовок и пять карточек слайдера
      $steps                 четыре этапа «Как мы работаем»
      $projects              шесть примеров реализации

  templates/template-melo-service.php
      $service_title, $service_image, $service_items
      $steps, $projects      то же, что выше

У вас стоит ACF Pro и есть тип записи projects - массивы сделаны так,
чтобы их можно было заменить на WP_Query или поля ACF, не трогая
разметку внутри foreach.

Иконки лежат SVG-спрайтом в template-parts/melo-header.php и рисуются
currentColor. Своя иконка: добавить <symbol id="melo-i-имя"> в спрайт и
указать это имя в поле icon массива $service_items.


ЧЕГО НЕ ЛОМАТЬ

1. Инлайновый скрипт в <head> файла melo-header.php. Он ставит класс
   melo-js и через 2.5 секунды включает аварийный показ, если
   melo-page.js не загрузился. Уберёте - при сбое скрипта страница
   окажется пустой: блоки до появления стоят в opacity: 0.

2. Появление блоков считается через getBoundingClientRect по событиям
   scroll/resize/load, а НЕ через IntersectionObserver. Наблюдатель
   отдаёт результат асинхронно и только при отрисовке кадра, а прокрутку
   браузер восстанавливает после выполнения скриптов - из-за этого при
   F5 на середине страницы видимая часть оставалась пустой.

3. У .melo-card__media, .melo-project__media и .melo-service__media
   подъём, тень и шторка перечислены ОДНИМ объявлением transition.
   Разносить нельзя: сокращённая запись заменяет весь список целиком.

4. wp_head() и wp_footer() в каркасе - без них отвалятся плагины и
   админ-панель.


ЧТО ОСТАЛОСЬ НА ВАШЕЙ СТОРОНЕ

  • Фотографии - плейсхолдеры, вырезаны из макета. Пропорции и пути
    проставлены, менять только файлы в img/melo/.
  • Логотип - растр 196x54. Для ретины нужен SVG.
  • Ссылки проектов ведут на "#" - подставьте реальные или замените
    массив на WP_Query по типу записи projects.
  • Кнопка «Все проекты» ведёт на /projects/ - поправьте, если адрес
    другой.
  • Контакты в подвале - рыба, переопределяются фильтром выше.
  • Ширина контента 1840px при 1920 (токен --container в начале
    css/melo-page.css). У сайта 95.05vw. Если нужно вровень с
    остальными страницами - поменяйте одно значение.
  • Шрифты Golos Text и Merriweather тянутся с Google Fonts. Для
    российского хостинга лучше положить локально.
