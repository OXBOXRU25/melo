# MELO — инструкции для агента

Файл читается автоматически (стандарт `AGENTS.md`: Codex, Cursor и другие).
Подробная история проекта — в `PROJECT.md`, читай его перед первой правкой.

## Что это за проект

Внутренние страницы сайта архитектурного бюро MELO в новой стилистике.
Заказчик — веб-студия OXBOX, сайт клиента живой: `melodesign.ru`,
WordPress с темой `oxboxwise`.

Две готовые страницы, отличаются только вторым блоком:

| Файл | Второй блок |
|---|---|
| `dizayn-interera-i-eksterera.html` | «Направления деятельности» — слайдер из 5 карточек |
| `arhitekturnoe-proektirovanie.html` | «Что входит в услугу» — список с иконками + картинка |

## Структура

```
assets/css/tokens.css       цвета, шкала кеглей, сетка, движение
assets/css/base.css         сброс, типографика, появление блоков
assets/css/components.css   все компоненты
assets/js/main.js           меню, слайдер, появление, шапка, параллакс
integration/                пакет для вставки в тему oxboxwise
tools/build-integration.mjs сборка этого пакета
tools/build-package.ps1     сборка автономного пакета (устарел, см. ниже)
PROJECT.md                  вся история решений и замеров
MELO_2.jpg                  исходный макет 1920×8828
```

**Правь исходники в `assets/`, не файлы в `integration/`** — они собираются
скриптом и перезаписываются:

```
node tools/build-integration.mjs
```

## Как отдаётся заказчику

Только пакет `integration/` — файлы, которые кладутся в действующую тему
`oxboxwise`. Отдельную тему WordPress (папка `wordpress/`) программист
клиента забраковал: при активации она заменяет весь сайт. Не предлагай её.

## Две защиты в пакете интеграции, и нужны обе

1. **Скоупинг под `.melo-page`.** Защищает сайт от нас: в нашем CSS есть
   сброс на `html/body/img/a/ul/h1-h4`.
2. **Префикс `melo-` у всех 112 классов.** Защищает нас от сайта. У темы
   заняты `container`, `btn`, `nav`, `nav__link`, `breadcrumbs`, `service`,
   `service__item`, `service__title`, `project__title`. Без префикса их
   правила протекают внутрь наших блоков по свойствам, которые мы не
   задаём: секция «Что входит в услугу» получила синий фон от их `.service`.

Единственный класс без префикса — `open-modal-os`, он их и стоит намеренно.

## Грабли, на которые уже наступали

- **Появление блоков — не `IntersectionObserver`.** Он отдаёт результат
  асинхронно и только при отрисовке кадра, а прокрутку браузер
  восстанавливает после выполнения скриптов: при F5 на середине страницы
  видимая часть оставалась пустой. Используется прямой
  `getBoundingClientRect` по `scroll`/`resize`/`load`.
- **Аварийный показ должен быть специфичнее прячущего правила**, а не
  просто ниже. Прячущий селектор длиннее, потому что описывает конкретный
  блок, и выигрывает молча — все фотографии остались бы закрытыми.
- **Один `transition` на элемент.** У `.card__media`, `.project__media`,
  `.service__media` подъём, тень и шторка перечислены одним объявлением:
  сокращённая запись заменяет весь список целиком.
- **Порядок правил при равной специфичности.** Снятие `aspect-ratio` на
  широких экранах лежало в медиазапросе выше объявления блока и молча
  проигрывало — страница вылезала за экран на 30px.
- **Щуп `*{transition:none}` не глушит псевдоэлементы.** Писать полностью:
  `*, *::before, *::after`. Иначе замер конечного состояния врёт.
- **Не пересобирать zip через `Compress-Archive`** — пишет обратные слеши,
  macOS распакует кашу. Нужен `System.IO.Compression.ZipArchive`.

## Как проверять работу

Не «на глаз», а замером. В проекте это делалось так:

- Скриншот в любом состоянии и ширине: `~/.claude/scripts/cdp-shot.mjs`
  (headless Chrome по DevTools-протоколу, умеет прокрутку, ховер, `--probe`).
- Геометрия и кегли — через `getComputedStyle` в DOM, а не по картинке.
  Скриншот годится, чтобы заметить кандидата, но не чтобы его утвердить.
- Адаптив — прогон по ширинам 375, 414, 600, 768, 900, 1100, 1440, 1920:
  переполнение, иерархия кеглей, тач-таргеты.
- Перед сдачей — `php -l` по всем PHP темы (`D:\AI\php\php.exe`).

## Особенности машины

- **Есть:** Node (`D:\AI\nodejs`), Git (`D:\AI\Git`), PHP 8.3 и Composer
  (`D:\AI\php\php.exe`), Chrome.
- **Нет:** Python, GitHub CLI (`gh`), системного ffmpeg.
- **PowerShell 5.1**: нет `&&`, `||`, тернарника. Файлы `.ps1` с кириллицей
  сохранять в UTF-8 **с BOM**, иначе разбор разваливается.
- **Bash**: бэктики внутри `node -e "..."` съедаются оболочкой — скрипты
  длиннее пары строк класть файлом и запускать `node файл.mjs`.

## Как работать с заказчиком

Павел — арт-директор, 18 лет в веб-дизайне, код не читает, судит вкусом.

- Его вердикт по виду — данные, а не каприз. Спорить можно про числа
  (контраст, кегль, замер), про «стало хуже» — исправлять.
- Перебор вариантов — его работа, а не метание. Не подталкивать к «давай
  закончим».
- Объяснять про дизайн, а не про реализацию.
- **Замеченное ошибочное называть сразу и ДО задачи**, а не после: если
  ограничение известно заранее (нет исходника, просядет качество), сказать
  в первой же строке.
- Обращение по-приятельски, но цифры и плохие новости — точные.

Полный свод правил студии лежит вне проекта, в `~/.claude/OXBOX-DESIGN.md`.
Если работаешь не в Claude Code — попроси у Павла копию, там накопленный
опыт по всем его проектам.
